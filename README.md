# Proxy-server_for_caching_cats

Кешуючий HTTP-проксі для JPEG із [http.cat](https://http.cat). Сервер
приймає запити за кодом стану, наприклад `/418`.

## Запуск

```powershell
npm ci
npm start -- -h 127.0.0.1 -p 3127 -c cache
```

Усі три опції обов'язкові. Довідка доступна через `node main.js --help`.
Відносний шлях кешу відраховується від кореня проєкту. Для перевірок
з чистого кешу можна передати нову підтеку, наприклад `cache/demo`.
Тека створюється під час першого HTTP-запиту.

| Метод | Дія | Результат |
| --- | --- | --- |
| GET | Віддати JPEG з кешу або завантажити його з http.cat | `200`, `Content-Type: image/jpeg`, `X-Image-Source: cache` або `http.cat` |
| PUT | Записати або замінити JPEG байтами з тіла запиту | `201` |
| DELETE | Видалити JPEG з диска | `200` або `404`, якщо файлу немає |
| Інші методи | Повернути перелік підтримуваних методів | `405`, `Allow: GET, PUT, DELETE` |

## Перевірка

- Виконайте команди з [test.txt](test.txt) у PowerShell із кореня репозиторію.
- Імпортуйте [колекцію](Lab5.postman_collection.json) у Postman. Укажіть
  корінь проєкту як робочу теку, щоб Postman прочитав
  [бінарний JPEG](fixtures/put-cat.jpg) за шляхом `fixtures/put-cat.jpg`.
  Якщо порт відрізняється, змініть змінну колекції `baseUrl`.
- Для двох повних запусків колекції використайте окрему порожню підтеку
  кешу. Колекція видаляє `418.jpg` у кожному запуску, тому наступний
  перший GET знову отримує картинку з http.cat.
